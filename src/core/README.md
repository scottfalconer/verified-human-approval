# Verified Human Approval: core (`verified-human-approval/core`)

The framework-neutral approval engine. It freezes proposals, checks current permissions, coordinates guarded execution in one database transaction, and stores execution records. Configure an `EvidenceSigner` to sign each receipt as the action commits. The package also supplies a signed audit log and receipt verification.

Storage sits behind interfaces, so a host such as a Drupal module can use its own: `ApprovalStore` (whose PHPDoc states the transaction rules, which `verified-human-approval/store-contracts` checks an adapter against) and `Audit\AuditStore` for the signed log's rows. `PdoApprovalStore` and `PdoAuditStore` are the SQLite adapters; their `initialize()` methods are installation steps. `verified-human-approval/doctrine` supplies both, and the passkey repository, on a Doctrine DBAL connection: SQLite, PostgreSQL, MySQL or MariaDB. Serving existing receipts needs no signing key: `new Evidence\EvidenceExporter()` returns each one as it was signed.

A host supplies an `ActionAdapter`, `Authorizer`, `PolicyProvider`, `ApprovalStore` and `ApprovalVerifier`. The action defines the exact effect, its version, preconditions, execution and postconditions. The supplied PDO store supports SQLite, and the Doctrine package SQLite, PostgreSQL, MySQL and MariaDB; either way, the action, permissions, credentials and approval records must share one connection. See the [integration contracts](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/integration-contract.md) and [security model](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/security-model.md).

The Symfony bundle wires these services into an application. The WebAuthn package supplies passkey verification and the offline evidence command. The [receipt guide](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/evidence.md) shows both checkout and installed-package commands. The command checks a receipt against the application's separately trusted public key, and the passkey signature too when given the credential's trusted record. An `EvidenceSigner` exposes its public key (`publicKey()`), which the Symfony bundle publishes so anyone can check its receipts.

Signed security events use `Audit\AuditLog(AuditStore $store, EvidenceSigner $signer, string $trustedPublicKey, ClockInterface $clock)`. The host supplies `AuditStore`; `Storage\PdoAuditStore` is the SQLite reference implementation and owns `initialize()`. Existing canonical audit records and signatures are unchanged. When migrating callers, wrap the shared PDO in `PdoAuditStore` and move schema initialization from `AuditLog` to that store. Append serialization must start before reading the global chain head, including an empty chain, and remain held until the enclosing host transaction ends.

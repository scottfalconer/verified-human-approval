# Verified Human Approval: core (`verified-human-approval/core`)

The framework-neutral approval engine. It freezes proposals, checks current permissions, coordinates guarded execution in one database transaction, and stores execution records. Configure an `EvidenceSigner` to sign each receipt as the action commits. The package also supplies a signed audit log and receipt verification.

Storage sits behind interfaces, so a host can keep its records in storage of its own: `ApprovalStore` (whose PHPDoc states the transaction rules, which `verified-human-approval/store-contracts` checks an adapter against) and `Audit\AuditStore` for the signed log's rows. `PdoApprovalStore` and `PdoAuditStore` are the SQLite adapters; their `initialize()` methods are installation steps. `verified-human-approval/doctrine` supplies both, and the passkey repository, on a Doctrine DBAL connection: SQLite, PostgreSQL, MySQL or MariaDB. Serving existing receipts needs no signing key: `new Evidence\EvidenceExporter()` returns each one as it was signed.

A host supplies an `ActionAdapter`, `Authorizer`, `PolicyProvider`, `ApprovalStore` and `ApprovalVerifier`. The action defines the exact effect, its version, preconditions, execution and postconditions. The supplied PDO store supports SQLite, and the Doctrine package SQLite, PostgreSQL, MySQL and MariaDB; either way, the action, permissions, credentials and approval records must share one connection. See the [integration contracts](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/integration-contract.md) and [security model](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/security-model.md).

The Symfony bundle wires these services into an application. The WebAuthn package supplies passkey verification and the offline evidence command. The [Verify a receipt](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/evidence.md) guide shows both checkout and installed-package commands. The command checks a receipt against the application's separately trusted public keys, and the passkey signature too when given the credential's trusted record. An `EvidenceSigner` exposes its public key (`publicKey()`), which the Symfony bundle publishes so anyone can check its receipts.

`Evidence\TrustedKeys` is the set of public keys the application has signed with, each an `Evidence\TrustedKey` with the window it signed in. Receipts and audit entries name their key and verify only inside its window, so the signing key can be rotated without breaking what the old key signed; a single public key is a one-key set without a window (`TrustedKeys::single()`). The [Verify a receipt](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/evidence.md#rotate-the-signing-key) guide gives the rotation and compromise procedures.

`ApprovalService` checks a stored request before it reports, exports or retries it: the status and result must agree with the execution record. With an `EvidenceSigner`, a completed request must also still carry the receipt signed as it committed, verified against the `TrustedKeys` passed as the service's last argument (`trustedKeys:`), or against the signer's current key alone when none are passed. A request that fails is refused with `record_integrity_error`, which is not a statement that nothing happened. So configure the signer before the first action runs, and pass every key the application has signed with once it has rotated. A stored request that can no longer be read back at all is refused the same way. The stores' lists, `recent()` and `ApprovalHistory::forResource()`, put an `UnreadableApproval` in its place, though `PdoApprovalStore`'s history cannot place a proposal that is no longer JSON. A state they list is as stored, so check it as the service does before showing its outcome. Its `assertConsistent()` checks only that its stored parts agree. With a signer, a completed state's receipt must also verify as signed at commit: `(new Evidence\ReceiptVerifier())->verify((new Evidence\EvidenceExporter())->export($state), $trustedKeys)['receiptSignedAt']` must be `Evidence\Receipt::COMMIT`. The [Verify a receipt](https://github.com/scottfalconer/verified-human-approval/blob/main/docs/evidence.md#use-verification-in-your-application) guide covers the details.

Signed security events use `Audit\AuditLog(AuditStore $store, EvidenceSigner $signer, TrustedKeys $keys, ClockInterface $clock)`; for the signer's key alone, pass `TrustedKeys::single($signer->keyId(), $signer->publicKey())`. `recordRotation()` records in the chain when the signing key changes, and `head()` returns the newest sequence and hash, a checkpoint to keep outside the application. The host supplies the `AuditStore`, such as `Storage\PdoAuditStore` on SQLite. A store must serialize appenders before it reads the head of the one chain, an empty chain included, and hold them off until the transaction the append runs in ends.

This package is developed in the [Verified Human Approval repository](https://github.com/scottfalconer/verified-human-approval). Open issues and pull requests there.

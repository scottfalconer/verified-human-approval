# Implemented extension contracts

Namespaces: `VerifiedHumanApproval\Core`, `VerifiedHumanApproval\WebAuthn`, `VerifiedHumanApproval\Doctrine`, `VerifiedHumanApproval\Bundle`, `VerifiedHumanApproval\StoreContracts`, `VerifiedHumanApproval\Demo`.

Core public value types and interfaces (all in `VerifiedHumanApproval\Core` unless stated):

- `Actor(string $userId, string $tenantId, ?string $delegationId = null)`: authenticated subject. Reviewer and initiator must match user/tenant; stored initiator delegation is independently rechecked at execution.
- `PreparedAction(string $actionId, string $version, array $target, array $effect, array $preconditions, array $display, array $placeholders = [])`. The bundle's review page reads `display.title` and, when present, `display.consequence` (what happens the moment it is approved, for a statement that does not already say so); both are frozen with the proposal.
- `ApprovalPolicy(string $actionId, string $version, string $statementTemplate, int $lifetimeSeconds = 600, bool $required = true)`.
- `ActionAdapter`: `id(): string`, `version(): string`, `prepare(Actor $actor, array $input): PreparedAction`, `assertPreconditions(Actor $actor, PreparedAction $action): void`, `execute(Actor $actor, PreparedAction $action): array`, `assertPostconditions(Actor $actor, PreparedAction $action, array $result): void`.
- `PolicyProvider::get(string $actionId, ?Actor $actor = null): ApprovalPolicy`: the rule for this action, for this person when one is given, so it can depend on their role.
- `Authorizer::assertAllowed(Actor $actor, PreparedAction $action): void` must reload current user/delegation authority using the transaction's database, not trust stored roles.
- `ApprovalVerifier::requestOptions(Actor $actor, string $challenge): array`, `verify(Actor $actor, string $challenge, array $assertion): VerifiedApproval`. Challenge is raw bytes. Verification and credential-counter persistence occur within the final transaction.
- `VerifiedApproval(string $credentialId, array $evidence)`.
- `ApprovalException(string $reason, string $message)` for deliberate rejection.
- `ExecutionGuard::assertExecuting(Actor $actor, PreparedAction $action): void`: application mutation services call this; service opens a narrow execution context only after all checks. No MCP argument can create it.
- `ExecutionGuard::current(): ?ExecutingApproval`, during `execute()` only: the executing approval's `requestId`, `actionId` and `approval` (`user_verified` or `not_required`; `userVerified(): bool`). An adapter writes the request id onto the change it makes, in the same transaction, to link that change (a published revision, say) to its evidence.
- `ApprovalObserver::completed(ApprovalState $state): void`: told about each executed action after its transaction commits, by the call that executed it, at least once (a call that recovers an ambiguous commit reports what it reads). It runs outside the transaction; an exception it throws is logged and cannot change the result.
- `ApprovalHistory::forResource(string $tenantId, string $resource, int $limit = 50): list<ApprovalState>`: optional, newest first, keyed by the prepared target's `resource`; records outlive the resource. `PdoApprovalStore` and `DbalApprovalStore` implement it (the Doctrine store indexes a `resource` that is a string or an integer). The host decides who may see which history.
- `ActionRegistry(iterable $actions)`, `get(string $id): ActionAdapter`.
- `ApprovalService(ActionRegistry $actions, PolicyProvider $policies, Authorizer $authorizer, ApprovalStore $store, ApprovalVerifier $verifier, ClockInterface $clock, ExecutionGuard $guard, ?EvidenceSigner $receipts = null, iterable $observers = [], ?LoggerInterface $logger = null)`: with `$receipts`, each execution's receipt is signed inside the completing transaction, and a signing failure means nothing executes. `$observers` are `ApprovalObserver`s; `$logger` records an observer's failure.
- `ApprovalService::request(Actor $actor, string $actionId, array $input, ?string $idempotencyKey = null, string $locale = 'en'): ApprovalState`.
- `ApprovalService::get(Actor $actor, string $requestId): ApprovalState` (ownership first, including completed results).
- `ApprovalService::begin(Actor $reviewer, string $requestId): Ceremony` (checks ownership, state and current eligibility; produces passkey options).
- `ApprovalService::complete(Actor $reviewer, string $ceremonyId, array $assertion): ApprovalState` (stored action only; no replacement arguments).
- `ApprovalService::cancel(Actor $reviewer, string $requestId): ApprovalState`.
- `ApprovalState` has `request: ApprovalRequest`, `status: string`, `reason: ?string`, `result: ?array`, `execution: ?array`, `proof: ?array`, `receipt: ?array`; `toArray(): array` is a safe status result. Only a non-null `proof` means a person approved it with a passkey. Status values pending, completed, invalidated, expired, cancelled, denied.
- `ApprovalRequest` has `id`, `canonical`, `digest`; `actor(): Actor`, `prepared(): PreparedAction`, `payload(): array`, `statement(): string`, `expiresAt(): DateTimeImmutable`. Stored canonical payload is authoritative and always checked against its digest.
- `Ceremony` has `id`, `requestId`, `nonce` (base64url), `challenge` (base64url), `expiresAt` (timestamp string), `options: array`, `consumed: bool`; `toArray()` returns ceremonyId/options/expiry, not a general approval capability.
- `ApprovalStore`: the storage and transaction boundary. Its PHPDoc states the nine rules an adapter must keep (own the root transaction, include every authoritative write, serialize the writers that matter, run the callback once, keep canonical bytes, enforce identity and immutability, handle every Throwable, recover from authoritative state, keep schema changes out of execution). The package `verified-human-approval/store-contracts` (`VerifiedHumanApproval\StoreContracts`) runs them against an adapter through a `StoreHarness`: `ApprovalStoreContract`, with `AuditStoreContract` (`AuditHarness`) for an `AuditStore` and `CredentialRepositoryContract` (`CredentialHarness`) for a `RevocableCredentialRepository`, the fixture application (`Fixture\*`, on a `Fixture\FixtureDatabase`, with a fixture schema per platform), `FaultingStore`, `FaultingSigner`, `Faults` (including pauses at `authority_checked` and `before_commit`) and `ProcessRace`. The SQLite PDO adapters pass them in the rollback journal and in WAL; the Doctrine adapters pass them on SQLite in both journals, PostgreSQL and MySQL (the server runs are named by `VERIFIED_HUMAN_APPROVAL_POSTGRES_URL` and `VERIFIED_HUMAN_APPROVAL_MYSQL_URL`). Require the same before relying on another adapter. On a database that locks rows, the contract also requires the application's reads to lock what the decision reads: an approval must never commit after a change to its grant, permission, content, passkey or policy that committed first.
- `Storage\PdoApprovalStore(PDO $pdo)` with `initialize(): void` owns approval tables on caller's SQLite PDO; `transaction(callable $callback): mixed` uses BEGIN IMMEDIATE, rejects unrelated nested transactions. Application tables, authorization rows, credential rows and approvals use this exact connection. `connection(): PDO` exposes it for demo wiring.
- The Doctrine package (`verified-human-approval/doctrine`, DBAL 4.4 or later; SQLite, PostgreSQL, MySQL 8.0.17 or later, MariaDB): `DbalTransaction(Connection $connection)` is the one root transaction the stores share. `run(callable $callback): mixed` refuses to start inside any other transaction (DBAL, ORM or driver; its message names `wrapInTransaction()` and Messenger's `doctrine_transaction` middleware) and outside auto-commit mode, begins through DBAL so an ORM flush nests as a savepoint, takes SQLite's write reservation before anything is read, runs PostgreSQL, MySQL and MariaDB at `READ COMMITTED`, runs the callback once, rolls back on any `Throwable` keeping the original error, and before commit releases a marker savepoint, so a root that was ended, replaced, committed implicitly or aborted by a swallowed failed statement fails instead of reading as a commit. `isActive(): bool`, `assertActive(): void`, `onRollback(callable $listener): void` (inside the transaction only), `forUpdate(): string` and `forShare(): string` (the lock clauses for the connection's database; empty on SQLite), `connection(): Connection`. `DbalApprovalStore(DbalTransaction)` implements `ApprovalStore` and `ApprovalHistory`, plus `recent(int $limit = 200)`; inside the transaction on row-locking databases it locks the request row, the ceremony row and the agent connection's request stripe. `DbalAuditStore(DbalTransaction)` locks its lock row before reading the head, joins any open transaction on the connection and owns a short one otherwise. `DbalCredentialRepository(DbalTransaction)` implements `RevocableCredentialRepository`, plus `forTenant(string $tenantId)`; ids are kept exactly and keyed by their SHA-256 digest; `update()` needs the approval transaction, `add()` and `revoke()` any transaction on the connection. Every read goes to the primary of a `PrimaryReadReplicaConnection`. `ApprovalSchema::tables(AbstractPlatform)`, `addTo(Schema, AbstractPlatform, bool $inPlace = false): Schema`, `install(Connection)` and `seed(Connection)` define, add, create and seed the tables (canonical JSON in text columns, never JSON or JSONB; `LONGTEXT`, `utf8mb4` and a binary no-pad collation on MySQL and MariaDB), never inside a transaction. With `doctrine/orm` 3.5 or later: `Orm\ApprovalSchemaListener(Connection)` for `postGenerateSchema`; `Orm\EntityAction`, an `ActionAdapter` whose final `execute()` clears the entity manager, loads `targets()` with pessimistic write locks, calls `apply()` and flushes, with `current()` (reload under a lock), `persist()` and a manager reset after rollback; `Orm\ProtectedEntityListener(ExecutionGuard, array $protected = [])` for `onFlush` and `preUpdate`, with `permit(object ...$entities)` during an approved execution, refusing other changes to `#[Orm\RequiresApproval]` entities or fields with `approval_required`.
- `Audit\AuditLog(AuditStore $store, EvidenceSigner $signer, string $trustedPublicKey, ClockInterface $clock)`: the signed, hash-chained security log, one chain for every tenant. `append(string $tenantId, string $type, string $subject, array $data): array`, `find(string $type, string $subject): ?array` (the newest entry that verifies), `verify(): array` (every entry, gaps and breaks). It builds, signs and checks entries (format `verified-human-approval/audit/v1`); the store only keeps rows.
- `Audit\AuditStore`: `append(callable $buildRecord): array` serializes appenders before reading the head (the highest stored row, even a damaged one), calls the builder once and inserts exactly its row; standalone it owns and commits a transaction, inside the host's it joins it and never ends it. `recordsFor(string $type, string $subject): iterable` (newest first) and `records(): iterable` (oldest first) return rows unfiltered. `Storage\PdoAuditStore(PDO $pdo)` is the SQLite adapter, with `initialize(): void`; a host transaction it joins must be started with `PDO::beginTransaction()`.

- `Evidence\EvidenceSigner`: `keyId(): string`, `sign(string $manifest): string` and `publicKey(): string`, the base64url Ed25519 key that verifies its signatures; `Evidence\SodiumEvidenceSigner` implements it.
- `Evidence\EvidenceExporter(?EvidenceSigner $signer = null, bool $signAtExport = false)`, `export(ApprovalState $state): array`: the evidence bundle (format `verified-human-approval/evidence/v2`). An original receipt comes back unchanged and no signer is touched, so serving evidence needs no private key; `$signAtExport` needs a signer. Without `$signAtExport` it refuses a completed action whose receipt signed at commit is missing (`receipt_missing`), since a deleted receipt is how an edit would be hidden. The receipt (`verified-human-approval/receipt/v2`) signs `signedAt`, `commit` or `export`, with the digests; `Evidence\ReceiptVerifier::verify()` returns it as `receiptSignedAt`.

The WebAuthn package owns its credential types/repository and PDO implementation, and the `verify-evidence.php` command. `RevocableCredentialRepository` (a `CredentialRepository` with `revoke(Actor $owner, string $id): bool`) is the raw storage that `AnchoredCredentialRepository(RevocableCredentialRepository $credentials, AuditLog $audit)` wraps: an adapter never overwrites, reassigns or reactivates an ID, treats ownership as user and tenant, compares and replaces on the active source (a zero-counter passkey writes back an identical source), and joins the host's transaction. Call `anchor()` in the same transaction as registration, and `revoke(Actor, string, array $context)` in the same transaction as its signed entry. `PdoCredentialRepository` implements it. It implements core ApprovalVerifier, plus trusted-host enrollment methods. No framework dependency is required by core or WebAuthn bridge. All production assertions use upstream verification; tests may use a distinctly test-only verifier.

Exactness uses stored canonical bytes, policy digest including resolved statement/version, prepared action behavior version, resource preconditions, current authority, fresh proposal-bound WebAuthn assertion, and postconditions. Completion consumes approval and writes business state and execution record in one transaction. Known execution rollback retires its ceremony; retry starts a fresh ceremony. A completed retry returns existing result, with ownership checked before disclosure.

Policy `required=false` is explicitly an unprotected request: it still checks authority/preconditions and records atomic outcome but has no passkey proof. A pending proposal from the old required policy cannot execute after any policy change. The browser and MCP adapters cannot edit policies; host administrator routes control configuration.

The Symfony bundle's `persistence: { driver: doctrine, connection: <name>, audit_public_key: ~, protected_entities: {} }` (exclusive with `store`, and needing `receipt_signer`) wires `DbalTransaction`, the three Doctrine stores, `AuditLog`, `AnchoredCredentialRepository` (aliased as `CredentialRepository`), the schema and protected-entity listeners, and the `verified-human-approval:install` command on that DoctrineBundle connection.

The Symfony bridge also requires `ActorProvider::assertCanReadApproval(ApprovalState): void` for current delegated result-read authorization. Core historical reads enforce ownership by user and tenant: the browser, or another delegation the person currently authorizes, need not be the delegation that asked. Delegation binding stays where it exists, for request-key reuse, keyless pending reuse and continuation. So the host checks its current read permission before every path that can return a stored result: a new request or a retry (a completed result can come back before write authority is checked), a continuation, a status read and an evidence export. The example checks `approval.read`, including idempotent request-result retrieval. An administrator's access to other people's results and evidence needs its own explicit policy.

Canonicalization delegates ordering to `root23/php-json-canonicalization` 1.0.1 and re-emits the ordered graph with PHP's unescaped Unicode/line-terminator flags. This compensates for upstream 1.0.1 escaping U+2028/U+2029 while [RFC 8785 section 3.2.2.2](https://www.rfc-editor.org/rfc/rfc8785.html#section-3.2.2.2) requires them literally. The accepted number profile is exact integers only. Tests preserve literal backslash-u text separately from those Unicode characters.

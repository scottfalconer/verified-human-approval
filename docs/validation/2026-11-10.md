## Reference-only compatibility and rollout limits

The reference root pins `symfony/mcp-bundle` to `1.0.0-BETA1 as 0.13.99`: MCP OAuth Bundle 1.2 still declares `^0.13`. Kernel and real HTTP acceptance exercise this combination. Ordinary strict root validation warns about the exact pin; `--no-check-all` deliberately excludes that check. The seven reusable package manifests retain full strict validation and have no OAuth issuer dependency or alias.

The OAuth reference uses schema 6. Existing reference data needs an explicit migration or a separate fresh runtime; this work performed neither a production migration nor a reset. Application permissions, original delegation mapping and trusted enrollment/recovery remain host responsibilities. A passkey adds exact-action approval, not missing permission. The reference-only challenge decorator and storage glue do not implement a replacement OAuth protocol.

Completion observers have no durable delivery guarantee. A host requiring reliable cache/index/notification work must use its own transactional outbox. Database receipts are application-signed execution reports; they are not independent observations of an external effect, proof of user comprehension or proof of a particular biometric.

Full CI matrix execution, published Packagist installation, external hosted-client reconnection and physical authenticator acceptance are separate from the recorded local checks.
